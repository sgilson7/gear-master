Part OneThree things this repo cannot do

Each of them is a hole with the same shape: a test that asks whether a thing exists, and no test that asks whether it works in the order a player meets it.

Nothing here has ever played a run. force_win and skip_to assign outcomes. completable.rs proves a key can exist before its door shuts. apply_preset seats twenty-two pieces somebody chose by hand. No test demonstrates that a build a seed's own shop can produce fights its way to any door — so no test can say whether every event in this game is reachable by a person.

The packer is a sampler. pack_francis draws three hundred boards from a fixed distribution, pays the full sixteen-fight acceptance gate on every one, and keeps the best. There is no local search anywhere in it. It costs 39.5 s a creature and lands in band by luck.

A theme is checked against the pool, never against the fight. MonsterTheme::allows filters which pieces a creature may draw from. Nothing asks whether the resulting fight reads as the theme, so a Burner that kills with one big blow passes every test in the repo.

Metric · DCR

The validity checker

Door coverage over forward, player-legal play. Three columns — offered, answered, branched — because the cheapest way to satisfy a coverage metric is to stand in front of things.

Metric · PQ

The packer

Creatures in band, seconds a creature, theme fidelity, and whether it can recover 48/50 from the owner's own tray. The bar is the sampler it replaces.

Metric · SCR

The pilot

Seeds cleared to a named target, board clears and game clears counted in separate columns. A fight past 30 s was decided by the clock.

The trap that governs everything below

An agent optimises the metric it is given, so ask what the cheapest way to satisfy each gate is before you ship the gate. Coverage's cheapest satisfaction is standing in front of doors — hence three columns. Fidelity's is carrying the vocabulary — hence every signature is a ratio over a fight log. A clear's is winning on the clock — hence board clears and game clears never share a column.

Part ThreeWhat “no access to the code base” is made of

Not discipline. The dependency graph.

Privileged critic, blind actor

The trainer may use the oracle: to score the pilot's boards, to shape reward, to build a value target. That is ordinary practice and it stays honest as long as the actor cannot consult it at inference. So the lab trains, the agent plays, and the thing evaluated is the agent alone with the oracle switched off.

Three lines about what a player may know

  • Anything on the screen is fair — it is in the observation.
  • Anything learned by playing is fair, across episodes and seeds. A person who plays seed 17 twenty times knows its shops; a person who has fought a Burner knows what a Burner does. Cross-episode memory is learning.
  • Anything read out of the tables is not, ever — and the crate graph makes it impossible rather than forbidden.

Which settles the fight-and-rewind question the old plan agonised over: replaying a seed is unlimited in training, because a player can restart, and evaluation is first sight — one forward play on a held-out seed, no restart, no fork, no rewind. Run::undo stays legal, because it is a button in the game.

A1 · the leak audit answered itself

This section used to flag Run::monster() as a leak to close: it hands back the coming creature's whole spec, gear included. It is not one. The window draws the creature's stats, then every item it will swing, then its whole board — under a comment saying the panel is a preview that exists so you can shop against what is coming, and that showing half of it would defeat the point. The view carries all of it.

What it withholds is the rest of the ladder, where the two interfaces disagree: the CLI prints every creature's outfit at every rung and the window shows only the next one. The console takes the window's answer, because telling an agent less than a player knows can only make a reachability claim stronger.

The proof is a transcript a person can type

The GUI is the reference surface — it calls 90 distinct Run methods. The CLI is eleven verbs short of the game: no reroll, barter, melt, crush, grow, lock, undo, give, passenger seating, relic payment or shelf pinning. A1 completes it, which makes every action typeable and turns crates/cli/tests/replay.rs — a script piped in twice and byte-compared — into the proof checker, with no new machinery.

A1 · foundThree things the lints caught before an agent played

None of them came from a failing feature. All three came from asking a question no test in this repo had asked: does the interface offer what the engine has, and does the screen read what the game reads?

The one that matters

THE PARISH finishes on no simulated census, and the handoff gives three dials for it. There is a fourth reason and it is not a dial: no interface could walk the perambulation. The CLI has perambulate now, and mouths to find out where to start. The window still has no button for any of the four, and a test fails the day one arrives.

The shop shows a price it will not charge

Run::price is the shelf price plus the markup, and Run::buy charges exactly that. Both interfaces draw the catalogue's number instead — the price before the markup. THE TOLLBOOTH answers with a 10% markup and says so in its receipt, and from that moment every shelf in the game displays a number it will not honour. The console shows what will be charged and the CLI was fixed with it; the window's three call sites are recorded for the owner.

A verb the game does not have

The console was written with an Enter verb for walking into a dungeon. The lint refused it: nothing in either interface calls enter_dungeon, because a run never walks into a dungeon — it is put in one, by answering a door, by a town's cellar, or by feeding an orb to a pedestal. This is the direction that matters most here: the lint stopped an agent from having an action a person does not.

A1 · the control, played

starter is the first thing in this repo's history to play a run forward through a player's own actions — seating what will sit, trying each anchor, keeping the one that finishes an item and taking the others back with the player's own undo. On the default seed it reaches rung 2 with six board clears in 145 presses, then stops climbing: two pieces of gear beat the Cave Rat in 4.5 s and lose to the Bog Toad in 7.2 s, for ever, because a Grinder knocks back on a loss. That is the zero every later milestone is measured against, and it was produced by playing rather than by argument.

Part FourWhy the packer is slow, in one number

Every candidate pays for sixteen fights, including the ones a single integer could have rejected. Measured at A0 on this machine: 8.0 s for a four-piece creature, 59.4 s for a twenty-one-piece one, and 242.5 s for Francis — which it then fails to author at all.

Measured at A0 · 020bc7c

Three hundred candidates, four minutes, and “nothing landed on the curve for rung 50: wanted 21.6s within 30%, best was a loss.” The sampler cannot author the game's final boss. That is the measured form of “does not work well”, and it is what A3 has to beat — not a better time on a creature the sampler can already do, but a board on the one it cannot.

Two fixes, and they are separable. Tier the objective so that the inner loop never simulates a fight, and improve rather than resample — local search from the best board found, with a memoised oracle and a per-slot incremental rebuild, instead of three hundred independent draws that never learn anything from each other.

The find that makes this work

loadout::Figures — the six county tolls — is a fight-free, player-visible score of what a board does per second: mana flow, damage in each lane, armour, the fastest item, curse resistance. It was written so a river could ask a board a question. It costs 42 nanoseconds — one seventeen-thousandth of a rung-50 fight — so a search that rejects a candidate on figures pays nothing for the rejection. It is also the signal a blind pilot uses to judge its own board the way a person does.

Target at A3: under 5 s a creature at a band-hit rate better than the sampler's, on eight performance cores. If it cannot beat the sampler at equal wall-clock, that is a finding rather than a failure — the space is smaller than it looks and the right investment is a better sampler.

Two things fall straight out, both at A2, both before any learning. A printer that scores all 78 creatures against their own themes and names the ones that do not read as what they claim — a balance finding the repo has never been able to produce. And a term in the packer's objective: score = acceptance + λ · fidelity, where λ = 0 recovers today's packer exactly, which is what makes the A3 comparison fair.

The same theme is the conditioning vector for the learned policy: ten one-hot, plus a fidelity weight, a coverage weight, difficulty and mode. One net serves all ten themes and both jobs, and the dial is a parameter rather than a retrain. A8 makes that falsifiable — train on eight themes, hold two out, and measure whether the held-out two are packed better than by the λ = 0 packer. A conditioning vector that does not generalise is a lookup table with extra steps, and the test says which one was built.

Part SixThe search is the expert; the net learns from it

The brief wants an agent that learns. The research says that on a deterministic, exactly-scored problem with a cheap simulator, search often wins. Expert iteration satisfies both, and it is not a compromise.

  1. The expert. Greedy recipe packing, NRPA and CEM local search, a beam over the menu. Slow, strong, and it produces labelled decisions: at this screen, with this doctrine, the search chose this and the episode reached this rung.
  2. The student. Policy and value heads over the observation. The policy is factored — first what kind of move, then which piece (≤ 12), then which anchor and rotation (≤ 384) — masked by the menu the console offers. The value head trains under Ranked Reward: "did this beat my own recent percentile", which manufactures a curriculum for a single-player problem that has no opponent to play against.
  3. The loop. The student's policy becomes the prior inside the search, which makes the expert faster, which produces better labels. The gate every turn is wall-clock: net-guided search must beat unguided search at equal seconds, or the net is recorded and switched off.

Reward is shaped, because a terminal win or loss over fifty rungs is a needle: the change in the player-visible figures after each placement; outcome and margin after each fight, so a win at 29 s and a win at 9 s do not score the same; a rung; and a novelty bonus the first time a run stands in front of a door it has never seen — which is what makes the agent a validity explorer rather than a win-maximiser, and its weight is the dial.

Why not PPO from scratch. It would work eventually and it wastes the asset. The environment is deterministic, the reward is exact and free, an expert exists, and the horizon per decision is short. PPO's strength — credit assignment through a stochastic, expensive environment — is the one thing this problem does not need. It stays on the shelf for the run-level layer if the beam turns out to be the weak part.

On this machine

An M2 Max: 12 cores, of which 8 are performance and 4 are efficiency, 32 GB unified, Metal. Burn with Autodiff<NdArray> first, Autodiff<Wgpu> measured against it on the real net — for nets this small, kernel-launch overhead often makes the CPU backend faster. Candle-metal is the fallback here rather than tch, since it needs no LibTorch. Nothing Python, ever.

And the efficiency cores make every throughput number a lie unless the thread count is written beside it: they are three to four times slower and rayon will happily use them.

Part SevenTen milestones, each with a gate

Two ordering rules, both inherited: no framework dependency before A6's gate opens, and no artifact enters the engine except as data.

  1. The ground, on this machine

    No agent code. Re-take every number the plan is priced in — fights a second, the sampler's real cost, the coverage census, the seed set — on this laptop, in release, on mains power.

    Met. Throughput 1.6–2.1× faster than the container's. 1,043 + 81 + 10 tests green, no warnings. Six of CLAUDE.md's counts corrected; census and 128 seeds written out.

  2. The console, and the CLI made whole

    The player's surface as a crate: verbs, the menu, the screen. The eleven missing CLI verbs. The leak audit on the coming creature.

    Met. 21 tests across two new crates, sub-second. Parity holds both ways; transcripts replay byte-identically. Engine suite unchanged at 1,043. Three findings — see below.

  3. The oracle and the theme meter

    Memoised, incremental scoring; the ported acceptance gate; the ten fidelity signatures. Plus the printer that scores all 78 creatures.

    Gate: cached equals recomputed over 10,000 lookups; the fidelity table exists and is discussed.

  4. The packer

    Greedy plus NRPA and CEM, theme-conditioned, tiered objective, parallel restarts. Two benchmarks: repack-from-tray, and creature boards against the sampler's own gate.

    Gate: ≥ 48/50 from the owner's tray and the friend's; more creatures in band than the sampler, faster.

  5. The pilot

    The blind agent plays a run through the console and nothing else. Three strategies: starter, greedy, beam. Every clear writes a transcript the CLI will replay.

    Gate: clear rate above zero at rungs 10, 25 and 50 in both modes, with proofs.

  6. Coverage as an objective

    The novelty reward, a targeted mode that plans to a named door, and the ledger. Anything unreached gets a second pass at ten times the budget before it is called unreachable.

    Gate: every gap classified — never offered, offered and refused, or answered and unpaid. Three different bug reports.

  7. The prior

    Behind a feature flag. Expert iteration from the search: factored policy masked by the menu, value under Ranked Reward, both conditioned on the doctrine.

    Gate: on held-out seeds, at equal wall-clock including inference, net-guided beats unguided — or it is written down and stopped.

  8. The loop

    Search with the prior, relabel, retrain. Curriculum by seed and by rung. The plateau test at 1× and 10×, with failures classified as evaluation or exploration.

    Gate: held-out clear rate, coverage and packer quality all above A3 and A4.

  9. The theme dial

    Train on eight themes, hold two out. Does conditioning change behaviour? Does fidelity rise without band accuracy falling? Report the confusion matrix — which themes the packer conflates is a statement about the themes.

    Gate: the two held-out themes pack better than λ = 0.

  10. In service

    The five county creatures packed rather than borrowed. The validity ledger published, re-runnable. The fourth reference build, if one was found, exported as a share code the suite fights without knowing an agent existed.

    Gate: engine suite green, no new engine dependency, no new non-data file in the engine.

Part NineFour decisions before A0

Each has a default so work can start without an answer. Each is one line to overrule. Eight more are in the spec.

E1Four crates, or two?

Four — console, oracle, agent, lab — makes the boundary a fact about the dependency graph rather than a promise in a doc comment, and turns "the agent has no access to the code base" into one cargo tree. Two (console and agent, with a source lint) is cheaper, weaker, and the thing most likely to erode.

Default: four
E4What may a theme cost in band accuracy?

Winning the fight is the first-order goal; reading as itself is the second. Unless a number is set now, the packer will quietly trade one for the other and nobody will notice which.

Default: reject any board losing more than 10% of band accuracy for fidelity
E8How many overnights?

The plan is priced for one M2 Max and about two weeks of wall-clock across A3 to A7, most of it unattended. Seeds shard trivially across a second machine if there is one.

Default: unattended overnight runs, one machine
E11Is 128 seeds right?

Sixty-four training and sixty-four held out. Fewer is faster and noisier; more is slower. The four seeds the repo already uses go in the training half so the held-out half stays clean, and no seed ever moves across the split or joins the set because the agent did well on it.

Default: 64 / 64
The failure mode to watch

The mission inherits the one this repo keeps meeting: an agent that reaches a target by a route no player could take, behind a green suite. The crate graph is the guard, and it is only as good as the test that asserts it — which is why that test is written at A1, before the first strategy exists, so there is never a proof nobody checked.
